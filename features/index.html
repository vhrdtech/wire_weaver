WireWeaver features and roadmap¶

This file is the single source of truth for what WireWeaver supports, what is being worked on and what is planned, for humans and AI agents alike. It replaces the external task tracker.

How to use this file¶

  • Status of each item:
  • ✅ done
  • 🚧 in progress or partially done (the note says what is missing)
  • 📋 planned
  • 💡 idea, not committed to
  • ⛔ blocked (the note says on what)
  • 🔍 probably done or obsolete, needs a check before closing
  • 🧪 done and tested on the host, the check on hardware is still open (the note says what to check)
  • Target is the release an item is planned for: v0.5 is the next release (the workspace is at 0.5.0, crates.io has 0.4.0). v0.5.x is the next compatible release after it: v0.5.1 if nothing turns out to be breaking, otherwise the next minor. No tag means not scheduled. grep 'v0.5' FEATURES.md gives the release scope.
  • IDs (SW-3, CLT-12) are stable: never renumber or reuse one. New items take the next free number of their area, even when they are inserted in the middle of it. Use the ID in commit messages, CHANGELOG entries and code TODOs (// TODO(SRV-4): ...). When talking to people, name an ID with a short slug from its title (SW-3 string-and-vec), never bare.
  • Items are grouped by area. Each area lists what works first (✅), then open items ordered by target.
  • When finishing work, update the item in the same change: mark it ✅, move it up to the done items of its area and add a pointer (docs page, crate, test or example). Don't delete done items. Move items that turn out to be obsolete to Dropped and superseded with a one-line reason.
  • This file is also rendered as the docs site's "Feature tracker" page (docs/features.md includes it), so indent nested lists and paragraphs inside an item by 4 spaces, as Python-Markdown requires. The "Features" page (docs/features_today.md) is generated from it and from tests/features_page/entries.md, which has a short line, a reading level and a docs link per item: an item that becomes done or in progress gets a line there, then run just features-page; just test fails until both are done.
  • New ideas go into the matching area as 💡. Small code-level gaps stay as TODO comments in the source; only those that limit users or block a feature get an item here.

Wire format (shrink_wrap, SW)¶

  • ✅ SW-1 Structs, plain enums and data enums, discriminant type selection with ww_repr.
  • ✅ SW-2 Option and Result, also inside Vec, as one-bit flags.
  • ✅ SW-3 String and Vec<T>, with special handling of Vec<u8>.
  • ✅ SW-4 Fixed size arrays, tuples and the unit type ().
  • ✅ SW-5 Bit-aligned integers: nibbles and u1..u32 (un); un8/un16 are forwarded to un32 for smaller flash.
  • ✅ SW-6 Variable length numbers: UNib32, UVlq32, and UVlq32Backfill for values known only after the rest is serialized.
  • ✅ SW-7 Borrowed and owned types: Sized and Unsized traits, RefStr/RefVec, borrowed types by default and Owned variants generated automatically.
  • ✅ SW-8 Evolvable by default: every struct and enum is Unsized; final_structure, self_describing and sized are opt-ins.
  • ✅ SW-9 TailBytes / TailBytesOwned: bytes that take up the rest of the buffer, written without a size; only valid as the last item. Generated API code puts them in place of byte slices, e.g. for return values and property values.
  • ✅ SW-10 EitherAnyVec: zero-copy, no-alloc array of Either elements of any types, with the L/R flags packed in groups of 8 instead of padding each element. Packs e.g. a list of Results tightly; used for multi-read and multi-call results (only multi-read exists so far).
  • ✅ SW-55 OptionAnyVec: zero-copy, no-alloc array of Option slots of any types (numbers, structs, lists, strings, a nested OptionAnyVec for a child level), only the present values written, in slot order without padding between them. A presence header up front in the smallest of four modes (all, dense bits, two-level bits, index list), self-delimiting so that readers with fewer or more slots than the writer read it (slots are only appended); a malformed header is an error. Writer takes the present set up front (SetBits over a bitset, any increasing iterator), OptionAnyVecWriter / in-place OptionAnyVecBuilder. For a trait level's properties in one update (API-38). See docs/serdes/special_types.md#optionanyvec-sparse-slots-of-any-types, docs/serdes/showcase.md.
  • ✅ SW-68 Word-wide bit writer and reader, the same bytes: BitWriter with a 32-bit accumulator flushed a word at a time, BitSink::put_block for packed blocks, write_un* / write_bool / UNib32 and the reader's read_un* / UNib32 through one 4-byte window and one bounds check per call. The FOC observe poll on an STM32H725 75.5 k cycles instead of 99.9 k at opt-level = 3 (121.5 k against 172.2 k at "z"), a FOC level batch from the store 36.8 k instead of 58.9 k; reads of UN numbers and UNib32 take 0.4-0.6x the instructions on a Cortex-M4F; about 1.5 KB more flash at "z". See docs/articles/series.md#the-bit-writer-and-reader-a-word-at-a-time, examples_mcu/mcu_qemu/src/bit_io.rs (qemu-bit-io, qemu-m4f-bit-io, stm32h725ig-bit-io-cycles).
  • ✅ SW-64 Series written straight from a SeriesStore, column by column, the same bytes as the item walk: SeriesStore::columnar / write_store (leaves, Option, arrays, tuples, derived structs and enums, by hand for NumericValue) and series::write_store_series, used by ww_stream's batchers on their own. Needs one variant per enum and Option over the rows (a prefix change falls back to the walk). One FOC level batch (21 x Series<T> + clock, n = 32, DeltaPacked): 74.9 k instructions on a Cortex-M3 instead of 143.5 k, 100 k cycles on an STM32H725 instead of 312 k (60 k against 125 k at opt-level = 3). See docs/serdes/series.md#from-the-store-column-by-column, shrink_wrap/shrink_wrap/src/series/store_write_tests.rs, examples_mcu/mcu_qemu (qemu-store-columns).
  • ✅ SW-63 Fast and small Series encoding on MCUs, the same bytes: about 6x fewer instructions per item on a Cortex-M3/M4F (Series<Timed<Ampere>>, n = 32: 341 with a fixed codec, 969 with SMALLEST; 25 200 cycles per batch of 32 on an STM32H725), and codec policies fixed at compile time (SeriesPolicy, FixedCodecs, DeltaPacked, the no_std default of ww_stream's batcher) that link only their own codecs: 15 KB of encoder flash on a Cortex-M3 instead of 91 KB (25 KB with a run-time CodecPolicy). See docs/serdes/series.md#cpu-and-flash-on-an-mcu, examples_mcu/mcu_qemu, examples_mcu/qemu_icount.
  • ✅ SW-62 SeriesStore and series size bounds: room for N items of a series type as a struct of arrays (empty_store, set, get), derived for structs (field stores) and enums (discriminants and every data variant's fields), by hand for ww_numeric::NumericValue (a variant byte and one payload as wide as the widest variant enabled): Timed<Ampere> takes 12 bytes per item with number types up to 32 bits, against 24 as items. SeriesColumns::MAX_ITEM_BITS / MAX_FIXED_BITS and Series::max_bytes(n): the worst case of a batch under any codec policy, None for strings and opaque fields. series(no_store) leaves the derived store out. Piece 1 of API-41. See docs/serdes/series.md#collecting-items-on-a-device-seriesstore, shrink_wrap/shrink_wrap/src/series/store_tests.rs, ww_stdlib/ww_si/tests/store.rs.
  • ✅ SW-61 RefVecBuilder<T>: a list written in place, element by element (push, extend, push_with for a nested builder or an element written by hand), finish writes the count; same bytes as RefVec::Slice, as the whole buffer, a struct field or an element of another list. A failed push undoes its element, with_max_len for MaxLen<RefVec<..>, N>, RefVecBuilderOwned for BufWriterOwned. A byte list also has extend_from_slice and write_bytes_with (a byte blob written by other means), which replace RefVecU8Builder. See docs/serdes/special_types.md#refvecbuilder-lists-written-in-place, shrink_wrap/shrink_wrap/tests/ref_vec_builder.rs.
  • ✅ SW-59 Tuple and unit structs in the derive: struct Celsius(f32);, struct Pair<'i>(u8, &'i str);, struct Marker; in every layout and size assumption, same bytes as the struct with the fields named; positional names _0, _1, ... in consts, C names and errors. #[flag] needs named fields. The API model has them as unnamed fields, dynamic clients and Python (a tuple, a single field its value, a unit None) read and write them. A unit struct is evolvable (it records its length inside a parent); with sized, final_structure, self_describing or fixed_layout it is a compile error, as it could never change. See docs/types.md, shrink_wrap/shrink_wrap/tests/tuple_structs.rs, tests/dynamic.
  • ✅ SW-58 validate = path derive directive: a function checking every struct value just read, so a derived type (and the API model it gives to dynamic clients) can still reject out-of-range data; used by ww_date_time::Year.
  • ✅ SW-57 ArrayString<N> / ArrayVec<T, N>: owned, no-alloc string/list types backed by a fixed-size array, same bytes on the wire as &str/String and Vec<T>, for an owned no-alloc field (a value_on_changed field of a string/list property in a no_alloc server, a settings value); Error::MaxLenExceeded rather than a cut value, for serializing, deserializing, push_str/push and TryFrom<&str> alike. docs/serdes/special_types.md#arraystring-arrayvec-owned-values-without-an-allocator.
  • ✅ SW-11 Alloc writer BufWriterOwned, SerializeShrinkWrap for &[u8], String as UFS.
  • ✅ SW-12 In-place builders used by the server codegen (event and error builders), and the manual patch-the-discriminant-later pattern (docs/serdes/showcase.md).
  • ✅ SW-13 Binary format documented in docs/serdes/wire_format.md, worked tricks in docs/serdes/showcase.md.
  • ✅ SW-14 Usable standalone as a dense data storage format (examples/minimal_shrink_wrap, examples/compare_wire_formats).
  • ✅ SW-34 Smaller code on small CPUs: BufReader / BufWriter reads and writes that keep an error instead of returning it (read_u8_latch, write_u32_latch, .., latched()), used by #[derive_shrink_wrap] for plain fields with one check per type; Error without payloads; one shared integer read and write; no division in UNib32. 19 to 20 % less code for a derived request/reply codec on RV32IC and Cortex-M0, same wire format. Numbers, where the rest goes and what is left to do: docs/serdes/code_size.md (measured by TEST-17).
  • ✅ SW-36 No length FIFO code for types without lengths: SerializeShrinkWrap::PUSHES_LEN, computed by #[derive_shrink_wrap] from the fields (default true unless Sized), lets to_ww_bytes and BufWriter::finish_for::<T>() end with finish_no_lens() at compile time, so the FIFO encoder is not linked: about 510 bytes less per such encoder on RV32IC (a struct of plain fields 1476 → 964). For types with lengths encode_len_fifo / write_nib are smaller (vec_ser 1378 → 1142). Same wire format (shrink_wrap/tests/pushes_len.rs, docs/serdes/code_size.md steps 4 and 5).
  • ✅ SW-37 RefVec of plain numbers without the decode pass: a list of u8..u128, i8..i128, f32 or f64 finds its end with one bounds check instead of reading every element (4096 bytes: 10 µs → 6 ns on a host), same result, errors and reader state as the pass, same wire format (shrink_wrap/tests/ref_vec_skip.rs, just fuzz-shrink-wrap-ref-vec). Costs 50 to 140 bytes of code in a decoder with such a list. Other Sized types keep the pass on purpose (stride is not size_bits, elements are validated there): docs/serdes/code_size.md.
  • ✅ SW-38 Latched reads of U1..U64 / I2..I64 fields: read like the integers of SW-34, with one error check per type (through a hidden DeserializeShrinkWrap::des_shrink_wrap_latch); a bit-packed struct decodes in 40 bytes less on RV32IC (886 → 846), 88 on RV32I. Same wire format, results and errors as reading field by field (shrink_wrap/tests/latched_reads.rs, just fuzz-shrink-wrap-latched). Nibble, u64 and varints are not latched: one such field costs more than it saves (docs/serdes/code_size.md).
  • ✅ SW-41 First error in types that mix latched and other fields: an error kept by a _latch read stops the reader (reads with a Result return it, no read moves), so a derived decoder with lists or nested types next to plain fields returns the first error again, as before SW-34. 20 bytes on a request/reply decoder (RV32IC), four forms measured (docs/serdes/code_size.md, shrink_wrap/tests/latched_errors.rs).
  • ✅ SW-43 C99 runtime (first step of API-26): shrink_wrap/c/shrink_wrap.{h,c}, the BufReader / BufWriter of the Rust crate for C: bits, nibbles, un8..un64, LE integers, floats, UNib32, UVlq32 / UVlq64, bytes and strings as borrowed views, split, lengths at the back and finish, Unsized values. No malloc, the first error kept as in SW-41 (a failing call moves nothing), octets through accessors so 16-bit char (TI C2000) works. Checked against the Rust crate with golden vectors and a proptest cross-check in both directions, also on truncated and corrupted input (shrink_wrap/c/tests, part of just test; just lint builds the C with -std=c99 -pedantic -Werror). How to use it: docs/c.md. TailSize, the series types and the _latch / finish_no_lens code size tricks are not ported.
  • ✅ SW-44 Fixed-layout fast path: #[derive_shrink_wrap] sees when a type's encoding is a fixed little-endian byte layout (a sized or final_structure struct, a sized or self_describing enum with a u8 / u16 / u32 ww_repr; fields only u8..u64, i8..i64, f32, f64 and arrays of them) and generates an offset const per field, ENCODED_LEN, and from_fixed / to_fixed that load and store at those offsets on the slice, no BufReader / BufWriter, nothing generic. The fixed_layout directive makes it a requirement (and allows nested fixed-layout types): a bool, Option, list, string, varint or bit-packed field is a compile error naming the field. Same bytes as ser_shrink_wrap (shrink_wrap/tests/fixed_layout.rs, 2000 random values per type). FixedLayout::write_c prints the matching C reader (offset defines and static inline loads) from the same derive, fixed_layout::write_c_header a whole header: the first generated C of API-26. Code size on Cortex-M0 for a header of eight integers: decode 484 → 276 bytes, encode 888 → 462 (docs/serdes/code_size.md). First user: chunky_mcu_updater's plan format (P2625 PROTO-3); it serves the busgen idea of P2401 #9oct-1433 for types without dynamic fields. Open: arrays of nested types, a C writer, 16-bit char targets in the C reader.
  • ✅ SW-45 Bit fields and a variable last field in the fixed-layout fast path: bool, U1..U32, I2..I32 and Nibble get compile-time bit offsets (most significant bit first, a Nibble on a 4-bit boundary, a byte field after them starting a fresh byte, as BufWriter packs them) and are read and written with shifts and masks, in Rust and in the C reader (sw_fixed_bits, sw_fixed_sbits). Option<T>, Result<T, E> and enums of unequal variants are allowed as the last field (one rule for all variable-length fields); their flags are bit fields, also where #[flag] moves them. MIN_LEN and fixed_len() next to ENCODED_LEN (the longest, the buffer to have ready). A nested type cannot share a byte with bits of its parent: a compile error says so. Every refusal says why and what to use instead. Byte-equal to ser_shrink_wrap on mixed bit runs, a run at the end, options, results, relocated flags and enum variants with both (shrink_wrap/tests/fixed_layout.rs); the generated C is built and run with every warning an error (just lint-c). A bit-packed sample on Cortex-M0: decode 652 → 276 bytes, encode 1034 → 560.
  • ✅ SW-46 Fixed head, sequential tail (head_tail): an opt-in wire format of its own for types with lists, strings and options anywhere. The head holds every fixed-width field at a constant offset (numbers, arrays, bit fields as in SW-45) plus a u16 count per list or string, the flag bit of each Option / Result and the head of each nested type; the tail holds the variable parts in field order. An enum is its tag, then its variant's head and tail. Generated by #[derive_shrink_wrap(head_tail)]: offset consts, HEAD_LEN, from_head_tail / to_head_tail / head_tail_len, the HeadTail trait (also implemented for every fixed-layout type) and a C reader (head readers plus a <name>_tail() walker, shrink_wrap::head_tail::write_c_header), built and run by just lint-c. Non-generic, size first: no BufReader / BufWriter, no length FIFO, no reversed lengths; the tail is a cursor (head_tail::Tail) that takes lengths it already knows. Lists are head_tail::List<'i, T> (items numbers or fixed-layout types of one length, read when iterated). No sw serdes and no owned version: one type, one format. Tests: exact bytes, round trips, every truncation, 200 000 random buffers, UTF-8, counts over u16 (shrink_wrap/tests/head_tail.rs). busgen's request and reply enums (size bench busgen_ht): 4626 bytes on Cortex-M0 and 6004 on RV32IC, against 4408 / 5762 hand-written and 6652 / 8210 derived (P2401 #9oct-1433). Open: head_tail types as ww API arguments (they have no sw serdes), lists of variable-length items, a C writer, u8 counts for short lists (MaxLen).
  • ✅ SW-52 head_tail views and variant writers: Type::view(buf) gives a TypeView<'_> without making the value: the lengths checked and the tail walked once, the head's fields read by accessors at their offsets when called (the same code as from_head_tail, one field at a time), lists, strings, options and nested views kept from the walk; an enum's view is an enum of its variants' views (a tuple variant of one nested type holds its view). Every enum variant gets Enum::write_<variant>(buf, fields..): the bytes of to_head_tail for that variant without making the value (the same write_ht code). HeadTail::View / view_ht, head_tail::view. Tests: values back from every accessor, writers byte-equal to to_head_tail, every truncation, 200 000 random buffers agreeing with from_head_tail. Size bench busgen_view: 4988 bytes on RV32IC and 3894 on Cortex-M0, 13 % and 12 % below the hand-written codec; busgen's firmware 5608 / 5090 bytes (UART / I2C image, fpga_tools BUS-12). View types are always pub (the View of a public trait). Open: lazy views of nested fixed-layout types (read when the view is made), a writer for structs.
  • ✅ SW-53 Numbers through fixed_layout::Le, out of line on RISC-V: generated fixed-layout and head_tail code reads and writes multi-byte numbers with Le::ld / Le::st on the bytes at the field (fixed_layout::at), one function per type on RISC-V (no unaligned loads), inline elsewhere (on Cortex-M0 the byte loads are smaller than the calls, measured). Under LTO ld passes its pointer through black_box: argument promotion would otherwise move the load into every caller. Bit-field bytes cleared once per head. busgen_ht on RV32IC 6004 → 5658; a type read or written in one place grows (fixed_ser 498 → 612, docs/serdes/code_size.md).
  • ✅ SW-54 #[cfg] on head_tail enum variants: passed to everything generated for the variant (consts, arms, view, writer, C text); a variant compiled out keeps its tag and reads as an unknown one. busgen's firmware builds only its bitstream family's requests with it.
  • ✅ SW-39 Byte-wise memcpy, measured, advice for very small targets: a firmware's own memcpy (and __aeabi_memcpy on Arm) of 22 bytes instead of the word-wise one of compiler_builtins: 324 bytes less on RV32IC, 304 on Cortex-M0, for every image that moves a value, at the price of speed and of replacing memcpy for the whole firmware. Code and downsides in docs/serdes/code_size.md ("Build settings"), measured with just size-bench --fw-features byte_memcpy. Nothing in shrink_wrap depends on it.
  • ✅ SW-40 Bit reads stay out of the lengths in the last byte: read_un8..read_un64 (and U1..U64, I2..I64) no longer read into the length nibble the last byte shares with the forward data, and a length is no longer read from bits the forward side has read; both are OutOfBounds.. errors. Malformed input only, every message the writers produce decodes as before. Checked against a bit-level model in every reader state of 1 to 3 byte buffers (buf_reader.rs bounds_every_state_every_read) and by round trips of random messages (shrink_wrap/tests/rev_nibble_bounds.rs).
  • ✅ SW-35 Exact ElementSize of enums: a sized / self_describing enum reports the discriminant plus one variant (ElementSize::one_of) instead of the sum of all variants without the discriminant; sized with variants of different sizes is a compile error; user types inside arrays, tuples, ranges and options are counted. Same wire format (shrink_wrap/tests/enum_size.rs, docs/serdes/size_assumptions.md). Unblocks reading RefVec<Sized T> in place.
  • ✅ SW-33 UVlq64: byte-based variable length u64, same big endian VLQ encoding as UVlq32, 1 to 10 bytes, uvlq64 field type in #[derive_shrink_wrap(..)], BufReader::read_uvlq64/BufWriter/BufWriterOwned::write_uvlq64 (shrink_wrap/src/vlq64.rs, docs/types.md, docs/serdes/showcase.md). No UVlq64Backfill (not asked for).
  • ✅ SW-19 Bounded lists and strings MaxLen<T, N>: a RefVec, Vec, &str or String with at most N elements, same bytes as T (a bound can be added, raised or removed without a new wire form), checked on serialize and deserialize (Error::MaxLenExceeded, never truncated). Works in derived types and in every API position (arguments, returns, properties, stream and sink items), visible in introspection (ww_self::Type::MaxLen), honoured by the dynamic client and Python; raising a bound is compatible, lowering or adding one breaking (ww api check). SerializeShrinkWrap::MAX_SIZE: Option<MaxSize>, the worst-case size of a type whose every part is bounded, feeds API-18. docs/types.md, docs/evolution/rules.md, shrink_wrap/tests/max_len.rs, tests/bounded, examples_mcu/mcu_qemu (qemu-bounded).
  • ✅ SW-15 Handle end of buffer when reading evolved fields: a field with #[default = ..] reads as its default only when it starts at the end of the data and runs out of it (Error::is_read_eob); a truncated or malformed value is an error. The flag of an evolved Option / Result falls back with it, #[default] works on any type and its value is used (an Option was always None). Same in the ww_self dynamic decoder. Padding bits of the old data's last byte read as 0, so bit-sized fields default to their zero value. Decided: no implicit defaults for Vec/String/Option fields without #[default], the attribute is what marks a field as added later (and what ww api check looks for). docs/serdes/derive.md#evolving-types, shrink_wrap/tests/evolution.rs.
  • ✅ SW-16 FutureVersion enum variant: an enum ending with #[future_version] Unknown(u32) reads an unknown discriminant into it instead of failing with EnumFutureVersionOrMalformedData, and writes it back; an Unsized enum skips the newer variant's fields with its size slot, sized / self_describing ones only survive new unit variants. Dropped and superseded¶

  • CLT-37 No millisecond per request from the accumulation window — superseded by request priority (CLT-50) and the fine window timer (CLT-53) (user, 27 Oct 2026). CLT-37 flushed whatever accumulated as soon as the tx task had nothing else waiting, for windows under 1 ms (TxInput::Idle, TxCore::wants_idle_flush, removed), so a request's latency depended on what else happened to be queued. Now default traffic waits for the window, never longer, and a request that must not wait says so with .urgent(). Its measurement (B135 rev B, USB HS, 21 Oct 2026): a property-like call 1.3 ms → 0.17 ms median, a 4 KB SD read 4.5 ms → 1.8 ms, CAN frames through a credit sink 3.8k → 7.2k/s.
  • STD-57 Quantity used at one fixed scale becomes Fixed — dropped (Roman, 27 Oct 2026): the per-use list of Quantity fields found none whose scale is fixed by contract, so nothing to change.
  • API-25 Refactor codegen to use an IR — decided against (18 Oct 2026). There are two wire-layout engines by design: shrink_wrap_derive keeps its own AST, as ww_self's own types are encoded with #[derive_shrink_wrap] and the derive can't depend on ww_self (a bootstrapping cycle); the dynamic path (ww_self to the dynamic client, Python, the CLI and GUI) computes the layout again from the introspection model, and generated C (API-26) is one more consumer of that model. Instead of an IR, the conformance matrix (TEST-23), one corpus of cases run through every consumer, is the contract that keeps them byte-identical; ww_self is the shared model for everything outside the derive. Fallback if drift ever bites: a dependency-free crate holding only the layout rules (bit offsets, flags, nibble alignment), called by both shrink_wrap_derive and ww_self, breaks no cycle.
  • STD-30 ww_gpio port access — dropped (Roman, 20 Oct 2026), Bank::read_inputs / write_outputs, PinLevel and the simultaneous_* capabilities removed before ww_gpio 0.1.0 was published. ww_gpio stays simple and low speed, one pin per call (IO family D9): many pins in one round trip are per-pin calls in one multi request (CLT-15, docs/std_library/ww_gpio.md#several-pins); several pins at one instant or with precise timing (bit-banged parallel buses, a strobe with its data lines) belong to the signal generator (STD-22) and the logic analyzer (STD-21). The extra methods only cost flash on every GPIO server.
  • SW-31 Delta / DeltaOfDelta, SW-32 XorFloat, SW-50 compressed sequences in APIs — superseded by Series<T> (SW-60): its numeric columns use the SW-31 prefix code with the delta or delta of delta predictor, its float columns the SW-32 XOR code, plus packed, constant and plain and the smallest picked per column, in every API position and in dynamic clients and Python (CLT-29); the types were removed (18 Oct 2026).
  • API-15 Return streams from functions — superseded by API-31 stream functions: #[stream(T)] fn name(args) opens a stream with typed arguments and result.
  • Document things (old notes) — superseded by docs/serdes/shrink_wrap.md and docs/evolution/rules.md; the notes described an earlier format (field ids, vlu16n_rev). Remaining ideas moved to their areas.
  • LEB numbers — superseded by UNib32 and UVlq32 (ULeb128 is still in the derive AST, unimplemented).
  • Field ids — decided against for now: fields are identified by position, which works well, and ids would add confusion together with flag relocation. The id leftovers in shrink_wrap_derive/src/transform/ can go.
  • Option and Result taking two id numbers — dropped with field ids; flags are separate fields.
  • Put length in front into a specified field — done as UVlq32Backfill.
  • CLI common blocks AST generation and excluding common blocks from the AST — done as API snapshots.
  • Compatibility check using AST signatures on connect — done.
  • Introspect as a trait, removed from ww_client_server — won't do.
  • WebUSB descriptors — only some browsers support WebUSB and it needs separate host support; NCM is more appealing, especially with pre-programmed unique IPs.
