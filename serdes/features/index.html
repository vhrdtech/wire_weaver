shrink_wrap features and roadmap¶

This file is the single source of truth for what shrink_wrap supports, what is being worked on and what is planned, for humans and AI agents alike.

How to use this file¶

  • Status of each item:
  • ✅ done
  • 🚧 in progress or partially done (the note says what is missing)
  • 📋 planned
  • 💡 idea, not committed to
  • ⛔ blocked (the note says on what)
  • 🔍 probably done or obsolete, needs a check before closing
  • 🧪 done and tested on the host, the check on hardware is still open (the note says what to check)
  • 🐛 known bug, not yet fixed (the note says how to hit it)
  • Target is the release an item is planned for (v0.5 is WireWeaver's next release, which these items were planned with). No tag means not scheduled.
  • IDs (SW-3, DER-8) are stable: never renumber or reuse one. New items take the next free number of their area. Use the ID in commit messages, CHANGELOG entries and code TODOs (// TODO(SW-20): ...). When talking to people, name an ID with a short slug from its title (SW-3 string-and-vec), never bare.
  • The items came from WireWeaver's FEATURES.md with their IDs, where shrink_wrap was developed. IDs of other areas (EVO, SRV, CLT, API, STD, TEST, ...) and paths outside this repository's crates (tests/conformance, wire_weaver_core, docs/api/..) are wire_weaver's. The C runtime (shrink_wrap_c: SW-43, SW-66, SW-75) and the conformance corpus (SW-67) stayed there, with their items.
  • Items are grouped by area. Each area lists what works first (✅), then open items ordered by target.
  • When finishing work, update the item in the same change: mark it ✅, move it up to the done items of its area and add a pointer (docs page, crate, test or example). Don't delete done items. Move items that turn out to be obsolete to Dropped and superseded with a one-line reason.
  • New ideas go into the matching area as 💡. Small code-level gaps stay as TODO comments in the source; only those that limit users or block a feature get an item here.

Wire format (shrink_wrap, SW)¶

  • ✅ SW-1 Structs, plain enums and data enums, discriminant type selection with ww_repr.
  • ✅ SW-2 Option and Result, also inside Vec, as one-bit flags.
  • ✅ SW-3 String and Vec<T>, with special handling of Vec<u8>.
  • ✅ SW-4 Fixed size arrays, tuples and the unit type ().
  • ✅ SW-5 Bit-aligned integers: nibbles and u1..u32 (un); un8/un16 are forwarded to un32 for smaller flash.
  • ✅ SW-6 Variable length numbers: UNib32, UVlq32, and UVlq32Backfill for values known only after the rest is serialized.
  • ✅ SW-7 Borrowed and owned types: Sized and Unsized traits, RefStr/RefVec, borrowed types by default and Owned variants generated automatically.
  • ✅ SW-8 Evolvable by default: every struct and enum is Unsized; final_structure, self_describing and sized are opt-ins.
  • ✅ SW-9 TailBytes / TailBytesOwned: bytes that take up the rest of the buffer, written without a size; only valid as the last item. Generated API code puts them in place of byte slices, e.g. for return values and property values.
  • ✅ SW-10 EitherAnyVec: zero-copy, no-alloc array of Either elements of any types, with the L/R flags packed in groups of 8 instead of padding each element. Packs e.g. a list of Results tightly; used for multi-read and multi-call results (only multi-read exists so far).
  • ✅ SW-55 OptionAnyVec: zero-copy, no-alloc array of Option slots of any types (numbers, structs, lists, strings, a nested OptionAnyVec for a child level), only the present values written, in slot order without padding between them. A presence header up front in the smallest of four modes (all, dense bits, two-level bits, index list), self-delimiting so that readers with fewer or more slots than the writer read it (slots are only appended); a malformed header is an error. Writer takes the present set up front (SetBits over a bitset, any increasing iterator), OptionAnyVecWriter / in-place OptionAnyVecBuilder. For a trait level's properties in one update (API-38). See docs/special_types.md#optionanyvec-sparse-slots-of-any-types, docs/showcase.md.
  • ✅ SW-68 Word-wide bit writer and reader, the same bytes: BitWriter with a 32-bit accumulator flushed a word at a time, BitSink::put_block for packed blocks, write_un* / write_bool / UNib32 and the reader's read_un* / UNib32 through one 4-byte window and one bounds check per call. The FOC observe poll on an STM32H725 75.5 k cycles instead of 99.9 k at opt-level = 3 (121.5 k against 172.2 k at "z"), a FOC level batch from the store 36.8 k instead of 58.9 k; reads of UN numbers and UNib32 take 0.4-0.6x the instructions on a Cortex-M4F; about 1.5 KB more flash at "z". See docs/articles/series.md#the-bit-writer-and-reader-a-word-at-a-time, examples_mcu/mcu_qemu/src/bit_io.rs (qemu-bit-io, qemu-m4f-bit-io, stm32h725ig-bit-io-cycles).
  • ✅ SW-64 Series written straight from a SeriesStore, column by column, the same bytes as the item walk: SeriesStore::columnar / write_store (leaves, Option, arrays, tuples, derived structs and enums, by hand for NumericValue) and series::write_store_series, used by ww_stream's batchers on their own. Needs one variant per enum and Option over the rows (a prefix change falls back to the walk). One FOC level batch (21 x Series<T> + clock, n = 32, DeltaPacked): 74.9 k instructions on a Cortex-M3 instead of 143.5 k, 100 k cycles on an STM32H725 instead of 312 k (60 k against 125 k at opt-level = 3). See docs/series.md#from-the-store-column-by-column, shrink_wrap/src/series/store_write_tests.rs, examples_mcu/mcu_qemu (qemu-store-columns).
  • ✅ SW-63 Fast and small Series encoding on MCUs, the same bytes: about 6x fewer instructions per item on a Cortex-M3/M4F (Series<Timed<Ampere>>, n = 32: 341 with a fixed codec, 969 with SMALLEST; 25 200 cycles per batch of 32 on an STM32H725), and codec policies fixed at compile time (SeriesPolicy, FixedCodecs, DeltaPacked, the no_std default of ww_stream's batcher) that link only their own codecs: 15 KB of encoder flash on a Cortex-M3 instead of 91 KB (25 KB with a run-time CodecPolicy). See docs/series.md#cpu-and-flash-on-an-mcu, examples_mcu/mcu_qemu, examples_mcu/qemu_icount.
  • ✅ SW-62 SeriesStore and series size bounds: room for N items of a series type as a struct of arrays (empty_store, set, get), derived for structs (field stores) and enums (discriminants and every data variant's fields), by hand for ww_numeric::NumericValue (a variant byte and one payload as wide as the widest variant enabled): Timed<Ampere> takes 12 bytes per item with number types up to 32 bits, against 24 as items. SeriesColumns::MAX_ITEM_BITS / MAX_FIXED_BITS and Series::max_bytes(n): the worst case of a batch under any codec policy, None for strings and opaque fields. series(no_store) leaves the derived store out. Piece 1 of API-41. See docs/series.md#collecting-items-on-a-device-seriesstore, shrink_wrap/src/series/store_tests.rs, ww_stdlib/ww_si/tests/store.rs.
  • ✅ SW-61 RefVecBuilder<T>: a list written in place, element by element (push, extend, push_with for a nested builder or an element written by hand), finish writes the count; same bytes as RefVec::Slice, as the whole buffer, a struct field or an element of another list. A failed push undoes its element, with_max_len for MaxLen<RefVec<..>, N>, RefVecBuilderOwned for BufWriterOwned. A byte list also has extend_from_slice and write_bytes_with (a byte blob written by other means), which replace RefVecU8Builder. See docs/special_types.md#refvecbuilder-lists-written-in-place, shrink_wrap/tests/ref_vec_builder.rs.
  • ✅ SW-59 Tuple and unit structs in the derive: struct Celsius(f32);, struct Pair<'i>(u8, &'i str);, struct Marker; in every layout and size assumption, same bytes as the struct with the fields named; positional names _0, _1, ... in consts, C names and errors. #[flag] needs named fields. The API model has them as unnamed fields, dynamic clients and Python (a tuple, a single field its value, a unit None) read and write them. A unit struct is evolvable (it records its length inside a parent); with sized, final_structure, self_describing or fixed_layout it is a compile error, as it could never change. See docs/types.md, shrink_wrap/tests/tuple_structs.rs, tests/dynamic.
  • ✅ SW-76 A refused value with its numbers — a validate = path function may return shrink_wrap::refused::Refused (the stored number read and the rule it broke: a range low..=high, NaN, ±∞, zero, a code that means no value) instead of a plain Error. The read still fails with SubtypeOutOfRange, so Error stays a fieldless u32 on firmware; with the refused feature (on with std) a reader made with with_refusal_slot(&slot) writes it into the caller's refused::Slot, shared by every reader split off it and by no other read, one pointer more in BufReader (40 to 48 B on a 64-bit host); from_ww_bytes_explained makes one and returns a ReadError ("6000 is out of 1..=5000"), the first refusal of the read. Without the feature (firmware) the reader doesn't grow and the numbers are dropped where they are made. A Series item's hook reports the plain error only. exact_units' Fixed, Index, IndexFrom1, Niched and Coded hooks moving to it is exact_units' side. Tests shrink_wrap/tests/refused.rs, docs/derive_reference.md#validate-path.
  • ✅ SW-58 validate = path derive directive: a function checking every struct value just read, so a derived type (and the API model it gives to dynamic clients) can still reject out-of-range data; used by ww_date_time::Year.
  • ✅ SW-57 ArrayString<N> / ArrayVec<T, N>: owned, no-alloc string/list types backed by a fixed-size array, same bytes on the wire as &str/String and Vec<T>, for an owned no-alloc field (a value_on_changed field of a string/list property in a no_alloc server, a settings value); Error::MaxLenExceeded rather than a cut value, for serializing, deserializing, push_str/push and TryFrom<&str> alike. docs/special_types.md#arraystring-arrayvec-owned-values-without-an-allocator.
  • ✅ SW-11 Alloc writer BufWriterOwned, SerializeShrinkWrap for &[u8], String as UFS.
  • ✅ SW-12 In-place builders used by the server codegen (event and error builders), and the manual patch-the-discriminant-later pattern (docs/showcase.md).
  • ✅ SW-13 Binary format documented in docs/wire_format.md, worked tricks in docs/showcase.md.
  • ✅ SW-14 Usable standalone as a dense data storage format (examples/minimal_shrink_wrap, examples/compare_wire_formats).
  • ✅ SW-34 Smaller code on small CPUs: BufReader / BufWriter reads and writes that keep an error instead of returning it (read_u8_latch, write_u32_latch, .., latched()), used by #[derive_shrink_wrap] for plain fields with one check per type; Error without payloads; one shared integer read and write; no division in UNib32. 19 to 20 % less code for a derived request/reply codec on RV32IC and Cortex-M0, same wire format. Numbers, where the rest goes and what is left to do: docs/code_size.md (measured by TEST-17).
  • ✅ SW-36 No length FIFO code for types without lengths: SerializeShrinkWrap::PUSHES_LEN, computed by #[derive_shrink_wrap] from the fields (default true unless Sized), lets to_ww_bytes and BufWriter::finish_for::<T>() end with finish_no_lens() at compile time, so the FIFO encoder is not linked: about 510 bytes less per such encoder on RV32IC (a struct of plain fields 1476 → 964). For types with lengths encode_len_fifo / write_nib are smaller (vec_ser 1378 → 1142). Same wire format (shrink_wrap/tests/pushes_len.rs, docs/code_size.md steps 4 and 5).
  • ✅ SW-37 RefVec of plain numbers without the decode pass: a list of u8..u128, i8..i128, f32 or f64 finds its end with one bounds check instead of reading every element (4096 bytes: 10 µs → 6 ns on a host), same result, errors and reader state as the pass, same wire format (shrink_wrap/tests/ref_vec_skip.rs, just fuzz-shrink-wrap-ref-vec). Costs 50 to 140 bytes of code in a decoder with such a list. Other Sized types keep the pass on purpose (stride is not size_bits, elements are validated there): docs/code_size.md.
  • ✅ SW-38 Latched reads of U1..U64 / I2..I64 fields: read like the integers of SW-34, with one error check per type (through a hidden DeserializeShrinkWrap::des_shrink_wrap_latch); a bit-packed struct decodes in 40 bytes less on RV32IC (886 → 846), 88 on RV32I. Same wire format, results and errors as reading field by field (shrink_wrap/tests/latched_reads.rs, just fuzz-shrink-wrap-latched). Nibble, u64 and varints are not latched: one such field costs more than it saves (docs/code_size.md).
  • ✅ SW-41 First error in types that mix latched and other fields: an error kept by a _latch read stops the reader (reads with a Result return it, no read moves), so a derived decoder with lists or nested types next to plain fields returns the first error again, as before SW-34. 20 bytes on a request/reply decoder (RV32IC), four forms measured (docs/code_size.md, shrink_wrap/tests/latched_errors.rs).
  • ✅ SW-44 Fixed-layout fast path: #[derive_shrink_wrap] sees when a type's encoding is a fixed little-endian byte layout (a sized or final_structure struct, a sized or self_describing enum with a u8 / u16 / u32 ww_repr; fields only u8..u64, i8..i64, f32, f64 and arrays of them) and generates an offset const per field, ENCODED_LEN, and from_fixed / to_fixed that load and store at those offsets on the slice, no BufReader / BufWriter, nothing generic. The fixed_layout directive makes it a requirement (and allows nested fixed-layout types): a bool, Option, list, string, varint or bit-packed field is a compile error naming the field. Same bytes as ser_shrink_wrap (shrink_wrap/tests/fixed_layout.rs, 2000 random values per type). FixedLayout::write_c prints the matching C reader (offset defines and static inline loads on a checked view, SW-79) from the same derive, fixed_layout::write_c_header a whole header: the first generated C of API-26. Code size on Cortex-M0 for a header of eight integers: decode 484 → 276 bytes, encode 888 → 462 (docs/code_size.md). First user: chunky_mcu_updater's plan format (PROTO-3); it serves the busgen idea for types without dynamic fields. Open: arrays of nested types, a C writer, 16-bit char targets in the C reader.
  • ✅ SW-45 Bit fields and a variable last field in the fixed-layout fast path: bool, U1..U32, I2..I32 and Nibble get compile-time bit offsets (most significant bit first, a Nibble on a 4-bit boundary, a byte field after them starting a fresh byte, as BufWriter packs them) and are read and written with shifts and masks, in Rust and in the C reader (sw_fixed_bits, sw_fixed_sbits). Option<T>, Result<T, E> and enums of unequal variants are allowed as the last field (one rule for all variable-length fields); their flags are bit fields, also where #[flag] moves them. MIN_LEN and fixed_len() next to ENCODED_LEN (the longest, the buffer to have ready). A nested type cannot share a byte with bits of its parent: a compile error says so. Every refusal says why and what to use instead. Byte-equal to ser_shrink_wrap on mixed bit runs, a run at the end, options, results, relocated flags and enum variants with both (shrink_wrap/tests/fixed_layout.rs); the generated C is built and run with every warning an error (just lint-c). A bit-packed sample on Cortex-M0: decode 652 → 276 bytes, encode 1034 → 560.
  • ✅ SW-46 Fixed head, sequential tail (head_tail): an opt-in wire format of its own for types with lists, strings and options anywhere. The head holds every fixed-width field at a constant offset (numbers, arrays, bit fields as in SW-45) plus a u16 count per list or string, the flag bit of each Option / Result and the head of each nested type; the tail holds the variable parts in field order. An enum is its tag, then its variant's head and tail. Generated by #[derive_shrink_wrap(head_tail)]: offset consts, HEAD_LEN, from_head_tail / to_head_tail / head_tail_len, the HeadTail trait (also implemented for every fixed-layout type) and a C reader (checked views since SW-79, shrink_wrap::head_tail::write_c_header), built and run by just lint-c. Non-generic, size first: no BufReader / BufWriter, no length FIFO, no reversed lengths; the tail is a cursor (head_tail::Tail) that takes lengths it already knows. Lists are head_tail::List<'i, T> (items numbers or fixed-layout types of one length, read when iterated). No sw serdes and no owned version: one type, one format. Tests: exact bytes, round trips, every truncation, 200 000 random buffers, UTF-8, counts over u16 (shrink_wrap/tests/head_tail.rs). busgen's request and reply enums (size bench busgen_ht): 4626 bytes on Cortex-M0 and 6004 on RV32IC, against 4408 / 5762 hand-written and 6652 / 8210 derived. Open: head_tail types as ww API arguments (they have no sw serdes), lists of variable-length items, a C writer, u8 counts for short lists (MaxLen).
  • ✅ SW-79 Checked C views of fixed-layout and head_tail types: the generated C readers no longer take a bare pointer. <name>_view(buf, len, &v) checks that the len bytes hold a whole value (every flag, tag, nested value and list count followed, an unknown enum tag refused) and makes a view, <name>_view_t; every reader takes a view, so there is no way to read a field without the length check. A view's len is the value's length (the next value of a stream starts there). Readers stay inside the view: an index past an array or list reads 0, an Option / Result payload, an enum variant (<enum>_as_<variant>) and a list item of a fixed-layout type are int readers with an out parameter that return -1 when it is not there. A caller that ignores a -1 reads zeros, never through NULL: every reader of an empty view reads 0 and a failed int reader leaves an empty view in *out. A type over 65535 bytes is an #error where size_t is 16 bits. Views and int readers are SW_NODISCARD (warn_unused_result on gcc and clang). No allocation; list lengths are checked before count * size can wrap on a 16-bit size_t. Same acceptance and lengths as Rust's from_fixed / head_tail::read (a C string is bytes: no UTF-8 check), checked on valid, truncated, empty, NULL, changed and random buffers of every test type with AddressSanitizer and UBSan and buffers of exactly the case's length (c_views_check_bounds in shrink_wrap/tests/fixed_layout.rs and head_tail.rs), and in the conformance matrix (a view from exactly the golden bytes, refused on every shorter prefix). C99 with -pedantic -Wconversion -Wsign-conversion -Werror on the host, MSP430, Cortex-M0 and RV32. Cost on Cortex-M0 at -Os: 4 bytes per reading function over the old readers with a hand-written length check, and about 6 more for the empty-view check (clang -Os, thumbv6m: 9 fixed-layout readers 148 → 204 bytes, 5 head_tail readers +24 bytes and an 8-byte empty view in .rodata per _as_<variant> used). Raised on chunky_mcu_updater PR #6.
  • ✅ SW-52 head_tail views and variant writers: Type::view(buf) gives a TypeView<'_> without making the value: the lengths checked and the tail walked once, the head's fields read by accessors at their offsets when called (the same code as from_head_tail, one field at a time), lists, strings, options and nested views kept from the walk; an enum's view is an enum of its variants' views (a tuple variant of one nested type holds its view). Every enum variant gets Enum::write_<variant>(buf, fields..): the bytes of to_head_tail for that variant without making the value (the same write_ht code). HeadTail::View / view_ht, head_tail::view. Tests: values back from every accessor, writers byte-equal to to_head_tail, every truncation, 200 000 random buffers agreeing with from_head_tail. Size bench busgen_view: 4988 bytes on RV32IC and 3894 on Cortex-M0, 13 % and 12 % below the hand-written codec; busgen's firmware 5608 / 5090 bytes (UART / I2C image, fpga_tools BUS-12). View types are always pub (the View of a public trait). Open: lazy views of nested fixed-layout types (read when the view is made), a writer for structs.
  • ✅ SW-53 Numbers through fixed_layout::Le, out of line on RISC-V: generated fixed-layout and head_tail code reads and writes multi-byte numbers with Le::ld / Le::st on the bytes at the field (fixed_layout::at), one function per type on RISC-V (no unaligned loads), inline elsewhere (on Cortex-M0 the byte loads are smaller than the calls, measured). Under LTO ld passes its pointer through black_box: argument promotion would otherwise move the load into every caller. Bit-field bytes cleared once per head. busgen_ht on RV32IC 6004 → 5658; a type read or written in one place grows (fixed_ser 498 → 612, docs/code_size.md).
  • ✅ SW-54 #[cfg] on head_tail enum variants: passed to everything generated for the variant (consts, arms, view, writer, C text); a variant compiled out keeps its tag and reads as an unknown one. busgen's firmware builds only its bitstream family's requests with it.
  • ✅ SW-39 Byte-wise memcpy, measured, advice for very small targets: a firmware's own memcpy (and __aeabi_memcpy on Arm) of 22 bytes instead of the word-wise one of compiler_builtins: 324 bytes less on RV32IC, 304 on Cortex-M0, for every image that moves a value, at the price of speed and of replacing memcpy for the whole firmware. Code and downsides in docs/code_size.md ("Build settings"), measured with just size-bench --fw-features byte_memcpy. Nothing in shrink_wrap depends on it.
  • ✅ SW-40 Bit reads stay out of the lengths in the last byte: read_un8..read_un64 (and U1..U64, I2..I64) no longer read into the length nibble the last byte shares with the forward data, and a length is no longer read from bits the forward side has read; both are OutOfBounds.. errors. Malformed input only, every message the writers produce decodes as before. Checked against a bit-level model in every reader state of 1 to 3 byte buffers (buf_reader.rs bounds_every_state_every_read) and by round trips of random messages (shrink_wrap/tests/rev_nibble_bounds.rs).
  • ✅ SW-81 An empty byte list writes no alignment in the borrowed derive: a RefVec<u8> field of a borrowed type (ser_shrink_wrap_vec_u8) wrote a padding byte for an empty list that started mid-byte, where every other writer and every reader take nothing; a field after it that starts mid-byte was read one byte early (a ww_tape TrackDef with an empty bundle failed with OutOfBoundsReadUN, a bool after the list read back wrong). The borrowed derive now writes the owned derive's bytes; bytes written before the fix still read where they did. Tests shrink_wrap/tests/empty_byte_list.rs (a property test: borrowed and owned give the same bytes), conformance cases struct.bytes.empty_end, struct.bytes.empty_mid, struct.bytes.mid.

  • 📋 DER-6 Check that TailBytes ends the outer type too — a struct ending in TailBytes used as a non-last field of an outer sized / final_structure type ("last in the first Unsized type on the way up") is not visible to the derive; needs a marker on the type, e.g. an associated const, and a compile-time assertion in the outer type.
  • 📋 DER-7 Prefix enum discriminants · v0.5.x.
  • 💡 DER-16 Where clauses naming the borrowed lifetime, for owned types — a generic type bounded on its lifetime (enum Batched<'i, T> where Timed<T>: SeriesColumns<'i>) can't be derived with owned: the owned side has no 'i and would need the bound as for<'i> SeriesColumns<'i>. ww_client_server::observe::Batched / BatchedOwned (API-39) are written by hand for that.
  • ✅ DER-8 #[cfg(..)] on enum variants — a variant keeps its discriminant in every configuration, a build without it reads Error::EnumVariantDisabled (docs/derive_reference.md). First user: ww_numeric::NumericValue, one cargo feature per number type (32 to 8 bytes in RAM with 32-bit types only). Not yet: #[cfg] on fields (it would change the wire format, should be a compile error), ww_si enums.
  • ✅ DER-23 A field written as a user type: #[wire(W)] (DER-19) with any W: WireAs<T>, not only integers: a field keeps a handle in Rust and writes the value it stands for (a one-byte handle in Rust, a full Magnitude on the wire; exact_units::Prefix's families use the integer form, Pow10(#[wire(i8)] Pow10Exp)). In a Series the field is an opaque run of W's bytes (series::WiredOpaque, the model marks it series-opaque) while store and cells keep the handle. Tests shrink_wrap/tests/wire_as_user.rs.
  • ✅ DER-24 An enum's tag in a niche: niche leaves the #[repr] the derive gives an enum (u32 for unib32) out, so Rust keeps the tag in a field's spare values (exact_units::Prefix with its families and Unknown(u16) is 4 B, not 8). The same bytes, discriminant() a match. Whether niche becomes the default for every enum is open (Roman). Tests shrink_wrap/tests/niche.rs.
  • ✅ DER-25 Narrow tag-only catch-all for niche enums — #[future_version] Unknown(u16) (or u8) on a self_describing / niche enum (DER-24) such as Prefix: the catch-all holds the tag only, so it doesn't widen the enum the way SW-47's Unknown(u32) would (Prefix 4 B instead of 8). The rule it enforces (Roman, 28 Oct 2026): every variant added after the enum's first release is tag-only, its numbers packed into the UNib32 tag, never bytes after it, so an older reader yields Unknown(tag), skips the self-describing value and decodes the rest of the message. The derive (a known discriminant beyond the field is a compile error, a read one fails as without the catch-all, series tag store of the field's type; also as cfg_attr(feature = .., future_version)), the width in the API model (FutureVersion::Variant::bits, None for u32 so older models keep their bytes), the dynamic client and the evolution checker (an appended discriminant beyond it is breaking), exact_units::Prefix, and the conformance case stdlib.si.quantity.unknown_scale (derive, dynamic, Python; C gap API-26).
  • ✅ DER-26 The derive accepts only what it writes: the type names uleb32..ileb128 (never written, a panic in codegen) and the field attribute #[id = N] (read and not used) are gone; an enum without any variant, and #[flag] or #[default = ..] on a tuple variant's field, are errors that name the cause. A discriminant of ub32 is written (it panicked the macro); a width of 0 or above 32 bits is an error.

Testing and code size (TEST)¶

  • ✅ TEST-17 shrink_wrap code size bench: just size-bench builds one bare firmware image per test case (plain struct, enum, list, bit fields, Option, decode or encode only, the request/reply codec of a small softcore firmware and the same by hand) for RV32I, RV32IC, Cortex-M0 and Cortex-M4F/M7 and prints .text + .rodata, or the largest symbols (size_bench, results in docs/code_size.md).

Dropped and superseded¶

  • SW-80 A small-field bit read without the word read — dropped (Roman, 14 Nov 2026): real firmware links the bit reader anyway. It was a read for bit fields of 8 bits or less that would spare a firmware without wider ones shrink_wrap's word read (about 250 B on a Cortex-M0+, since EVO-76 linked by every server for Request's 3-bit priority). Tried while landing EVO-76: a take_bits8 behind read_un8 / read_un8_latch brought the one-method floor from +260 to +108 B, but bits_de (just size-bench, small and wide fields together) grew 704 → 888 B on thumbv6m, as both reads are linked.
  • SW-31 Delta / DeltaOfDelta, SW-32 XorFloat, SW-50 compressed sequences in APIs — superseded by Series<T> (SW-60): its numeric columns use the SW-31 prefix code with the delta or delta of delta predictor, its float columns the SW-32 XOR code, plus packed, constant and plain and the smallest picked per column, in every API position and in dynamic clients and Python (CLT-29); the types were removed (18 Oct 2026).
