Basic

Fixed numbers¶

A Fixed is a number whose type says what it measures. Fixed<U, P, T, B> has four parts, and the thermometer uses all of them:

Part Says In the thermometer's Rate In its Gain
U the unit Hertz Ratio, a number without a unit
P the step: what 1 stands for One, steps of 1 Hz One
T the storage on the wire u16 u8
B the bounds Range<1, 1000> Range<1, 16>

On the wire and in memory a Fixed is exactly its T. A timeout kept as shared_us: u64 becomes Fixed<Second, Micro, u64> with the same bytes, and the introspection data then says microseconds instead of leaving you to trust a field name. The exact_units crate defines the type; Numbers with units explains how it relates to ww_si.

Declaring a Fixed¶

An API crate names each Fixed it uses once, as a type alias, and uses the alias in its traits. These are the thermometer's three, from book_units.rs:fixed_types:

/// Sampling rate: 1 Hz to 1000 Hz in steps of 1 Hz.
type Rate = Fixed<Hertz, One, u16, Range<1, 1000>>;
/// Amplifier gain: 1 to 16, no unit.
type Gain = Fixed<Ratio, One, u8, Range<1, 16>>;
/// A temperature in steps of 0.01 K, from -327.68 °C to 327.67 °C.
type Temperature = Point<Celsius, Fixed<Kelvin, Centi, i16>>;

Temperature is a Point of a Fixed. A point is a reading on a scale that starts somewhere, and Temperatures and other points explains why the thermometer needs one.

A value comes from try_new, which checks it, or from bounded, which panics on a value outside the bounds and fails the build in const code. Display shows the number with its unit, and Debug shows the type's meaning too. The lines below come from book_units.rs:fixed_values:

let rate = Rate::try_new(50).unwrap();
let gain = Gain::bounded(8);
let timeout = Micros::<u32>::new(1500);
println!("{rate}");
println!("{gain}");
println!("{timeout}");
println!("{gain:?}");

They print:

50 Hz
8
1500 µs
Ratio(8 u8, 1..=16)

A Gain has no unit, so it prints as the plain number 8.

The same bytes as the plain number¶

A Fixed costs nothing on the wire. book_units.rs:fixed_bytes writes four values and checks their bytes:

let mut buf = [0u8; 8];
let timeout = Micros::<u32>::new(1500);
assert_eq!(
    timeout.to_ww_bytes(&mut buf).unwrap(),
    [0xdc, 0x05, 0x00, 0x00]
);
// the plain u32 has the same four bytes
assert_eq!(
    1500u32.to_ww_bytes(&mut buf).unwrap(),
    [0xdc, 0x05, 0x00, 0x00]
);
// a Gain is one byte, a Rate two
assert_eq!(Gain::bounded(8).to_ww_bytes(&mut buf).unwrap(), [0x08]);
assert_eq!(
    Rate::try_new(50).unwrap().to_ww_bytes(&mut buf).unwrap(),
    [0x32, 0x00]
);

The 1500 µs timeout has the four bytes of the u32 1500, and the Gain has the one byte of the u8 8. Nothing about the unit, the step or the bounds is sent. Both sides of a link know them from the API, and the type checks them on each side.

A temperature and the plain i16 with the same value have the same two bytes. The unit, the step and the origin are in the type only.

A Fixed therefore replaces a bare integer in a property at no cost. It also keeps the device and the host from disagreeing about what the integer means: both read the same type.

Aliases for the common cases¶

The common units have aliases, so Millis<u16> is the same type as Fixed<Second, Milli, u16>. book_units.rs:aliases shows two of them:

let window = Millis::<u16>::new(250);
let uptime = Micros::<u64>::new(1_730_000_000_000_000);
// an alias is the same type under a shorter name
let same: Fixed<units::Second, ww_si::prefix::Milli, u16> = window;
assert_eq!(same, window);
assert_eq!(uptime.to_string(), "1730000000000000 µs");

The other aliases are Secs, Nanos, Minutes, Hours, Days and Hz, the byte sizes Bytes, Kibibytes, Mebibytes and Gibibytes, Count<Of, T>, Percent, Permille, Ppb and Duty16, the Q formats and the binary angles. A moment in POSIX time is a Point of origins::UnixEpoch, aliased UnixSecs, UnixMillis, UnixMicros and UnixNanos. The exact_units book lists them in its aliases table.

  • Unit algebra multiplies and divides them, with the result's unit as a type.
