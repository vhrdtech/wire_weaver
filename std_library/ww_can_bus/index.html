ww_can_bus¶

Part of the IO trait family. ww_can_bus is the WireWeaver API of CAN controllers: a USB-CAN adapter, a gateway, a node with a CAN port, a bus analyzer or debugger. The host configures the bus, sends and receives classic, CAN FD and CAN XL frames, and watches the controllers' error state. It is no_std by default and depends on wire_weaver and ww_si (Baud bit rates, Hertz clocks, Ohm terminators, Second timestamps).

[dependencies]
ww_can_bus = "0.1"                                    # classic and FD
ww_can_bus = { version = "0.1", features = ["xl"] }   # plus CAN XL

Traits¶

Trait What it is Who implements it
Can One controller with its transceiver: configure, receive, send, error state; optional items for everything only some controllers have Every device
CanGroup Controllers that share clock, power and message RAM (all FDCAN instances of an STM32): interface[] of Can, enable / disable, clock source and frequency, group-wide performance Devices that mirror such hardware
CanTimeTriggered Time-triggered CAN (ISO 11898-4) of one controller Controllers with TTCAN (FDCAN1 of an STM32H7)
CanXl CAN XL frames of one controller (xl feature) Controllers with CAN XL

A simple bridge puts its controllers straight into its API and implements the six required items of Can:

#[ww_api_root]
trait Bridge {
    ww_impl!(can[]: ww_can_bus::Can);
}

A device that mirrors its hardware puts a group there instead, with the time-triggered and XL parts next to it as arrays indexed like the controllers (valid only at indices that have the hardware):

#[ww_api_root]
trait Analyzer {
    ww_impl!(can: ww_can_bus::CanGroup);                 // can.interface[i]
    ww_impl!(can_tt[]: ww_can_bus::CanTimeTriggered);    // can_tt[i] is controller i
    ww_impl!(can_xl[]: ww_can_bus::CanXl);               // can_xl[i] is controller i
}

Can¶

#[ww_trait]
pub trait Can {
    fn capabilities() -> Capabilities<'i>;
    fn configure(config: CanConfig) -> Result<CanConfig, CanError<'i>>;
    fn config() -> CanConfig;
    property!(ro status: Status);
    #[counted]
    stream!(rx: RxFrame<'i>);
    #[credit]
    sink!(tx: TxFrame<'i>);

    #[optional] fn set_mode(mode: Mode) -> Result<Mode, CanError<'i>>;
    #[optional] fn recover() -> Result<(), CanError<'i>>;
    #[optional] fn tx_abort() -> u32;
    #[optional] #[counted] stream!(tx_events: TxEvent);
    #[optional] #[counted] stream!(bus_errors: BusError);
    #[optional] fn protocol_status() -> ProtocolStatus;
    #[optional] property!(ro bus_load: BusLoad);
    #[optional] fn detect_timing(candidates: MaxLen<RefVec<'i, Timing>, 16>, per_candidate: Second)
        -> Result<Option<CanConfig>, CanError<'i>>;
    #[optional(filters)] fn set_filters(filters: FilterConfig<'i>) -> Result<(), CanError<'i>>;
    #[optional] fn set_layout(layout: MemoryLayout) -> Result<MemoryLayout, CanError<'i>>;
    #[optional(rx_buffers)] fn rx_buffer(index: u16) -> Result<Option<BufferedFrame<'i>>, CanError<'i>>;
    #[optional(tx_buffers)] fn tx_buffer(index: u16, frame: Option<TxFrame<'i>>, period: Option<Second>)
        -> Result<(), CanError<'i>>;
    #[optional(transceiver)] fn set_transceiver(mode: TransceiverMode) -> Result<TransceiverMode, CanError<'i>>;
    #[optional(transceiver)] property!(ro transceiver_state: TransceiverState);
    #[optional(terminator)] fn set_termination(termination: Termination) -> Result<Termination, CanError<'i>>;
    #[optional(terminator)] property!(ro termination: Termination);
    #[optional] fn test_pins(tx: TxPin) -> Result<BusLevel, CanError<'i>>;
}
Item Required What it is for
capabilities() ✓ Controller clock, bit timing limits, FD and TDC, modes and options, FIFO / buffer / filter counts, memory, timestamps, transceiver modes, terminator values
configure(CanConfig) ✓ Mode, nominal and data bit timing, TDC, options and bus-off recovery in one call, answered with what was set
config() ✓ The configuration in effect, for a host attaching to a running node
status ✓ Error state, TEC / REC and the last protocol errors; observable, so a bus-off or a wake-up reaches the host without polling
rx ✓ Received frames, a counted stream (unit: frame) with the receive time in the head
tx ✓ Frames to send, a credit sink: the host never overruns the device's TX queue
set_mode Switch the mode alone, keeping timing, filters and layout (see Debuggers)
recover() Start the bus-off recovery on request
tx_abort() Drop every frame queued and not on the bus yet
tx_events When each sent frame went on the bus, with its marker and how long it waited, or why it didn't
bus_errors Every error detected on the bus: kind, phase, direction
protocol_status() The controller's raw protocol state
bus_load Bus load the device measures, sent once per window
detect_timing Find the bit timing of a running bus
set_filters (filters) Acceptance filters: exact ID, mask or range, into a FIFO (optionally high priority), a dedicated buffer, or rejected
set_layout Divide the message memory between filters, FIFOs, buffers and TX events
rx_buffer (rx_buffers) The latest frame of a dedicated RX buffer, without streaming every frame
tx_buffer (tx_buffers) A dedicated TX buffer: send once, or cyclically every period by the device
set_transceiver, transceiver_state (transceiver) Transceiver standby / silent / sleep, bus wiring faults
set_termination, termination (terminator) A switchable terminator (relay, MOSFET)
test_pins Production test: drive TX, read RX

        "can.rx_buffers", "can.tx_buffers", "can.transceiver", "can.terminator", "can.test_pins"

);

CanGroup¶

#[ww_trait]
pub trait CanGroup {
    ww_impl!(interface[]: Can);
    fn group_capabilities() -> GroupCapabilities<'i>;
    fn enable() -> Result<GroupClock, CanError<'i>>;
    fn disable() -> Result<(), CanError<'i>>;
    property!(ro group_state: GroupState);
    #[optional(clock)] fn set_clock(clock: GroupClock) -> Result<GroupClock, CanError<'i>>;
    #[optional] fn performance() -> Performance;
}

On STM32 every FDCAN instance hangs off one kernel clock and one message RAM: none can be clocked, powered down or re-laid out alone. CanGroup is that hardware. The group starts disabled (clock off, its lowest power state); enable() clocks it with the source and frequency set last (or the device's default) and answers the clock in effect, then each interface[i] is configured on its own. disable() needs every controller in Mode::Off.

Advanced nodes pick the clock to hit an exact bit timing: set_clock(GroupClock { source, frequency }) while disabled, from GroupCapabilities::clock_sources (name and frequency range of each), answered with the nearest frequency the dividers reach. The controllers then report that clock in Capabilities::clock and count their time quanta in it. A bridge leaves set_clock out and runs on the default. A standalone controller with its own oscillator choice (MCP2518FD) is a group of one.

performance() is what the group guarantees together (frames and bytes per second passed on without loss): a device whose controllers share a CPU or a link to the host knows it, the host can't.

Frames¶

pub struct Frame<'i> {
    pub id: CanId,                                  // Standard(U11) or Extended(U29)
    pub kind: FrameKind,                            // Data, Remote { len }, Fd { brs, esi }, DataLongDlc { dlc }
    pub data: MaxLen<RefVec<'i, u8>, MAX_DATA_LEN>, // up to 64 bytes
}

CanId::standard(0x123) and CanId::extended(0x18FF_0001) build an ID (None when out of range). FrameKind::DataLongDlc is a classic frame with 8 bytes and a DLC of 9-15 on the wire, for bus debuggers.

A received frame is an RxFrame { frame, filter }, filter being the index of the filter element that accepted it (None without filters or for non-matching frames). A frame to send is a TxFrame { frame, marker }: the marker comes back in the frame's TxEvent, so a host matches events to what it sent (M_CAN's message marker, MCP2518FD's sequence number, gs_usb's echo ID). On the wire a classic standard frame with 8 bytes takes 12 bytes as an RxFrame or TxFrame, a 64-byte FD frame with a marker 69.

CAN XL¶

CAN XL frames carry up to 2048 bytes, and a credit sink sizes the device's buffer for its largest item. So they are not part of Frame but of CanXl, behind the xl cargo feature: devices without XL neither reserve 2 KiB buffers nor carry the types.

#[ww_trait]
pub trait CanXl {
    fn configure_xl(config: Option<XlConfig>) -> Result<Option<XlConfig>, CanError<'i>>;
    #[counted] stream!(rx_xl: XlFrame<'i>);
    #[credit] sink!(tx_xl: XlTxFrame<'i>);
}

XlFrame has the 11-bit priority ID, VCID, SDU type, SEC, acceptance field and 1-2048 data bytes. XlConfig sets the XL data phase timing, TDC, PWM symbols for transceiver mode switching (CAN SIC XL) and data phase error signalling; it needs CAN FD configured on the controller. A device sending full-size XL frames takes WireWeaver messages of at least 2.1 KiB.

Configuration¶

pub struct CanConfig {
    pub mode: Mode,                       // Off, Config, Normal, Restricted, ListenOnly, Internal/ExternalLoopback, Test, Sleep
    pub nominal: Timing,                  // arbitration phase
    pub fd: Option<FdConfig>,             // data phase timing, TDC, ISO / non-ISO; None: classic only
    pub options: Options,                 // one_shot, presume_ack, triple_sample, tx_pause, tx_order, rx_overflow,
                                          // edge_filtering, protocol_exception, wake_on_bus
    pub bus_off_recovery: Option<Second>, // recover by itself after this long; None: wait for `recover`
}

pub enum Timing {
    Rate { rate: Baud, sample_point: u16 }, // sample point in tenths of a percent
    Segments(BitTiming),                    // prescaler, seg1, seg2, sjw in time quanta
}

A host asks for a bit rate and sample point, or for exact segments; configure always answers with segments, so the host sees what the controller runs at. BitTiming counts like SocketCAN and the M_CAN NBTP register: a bit is 1 + seg1 + seg2 quanta of prescaler clock periods, sampled after 1 + seg1, so BitTiming::bit_rate(clock_hz) and BitTiming::sample_point() follow from the answer and Capabilities::clock. Capabilities::nominal / data give the segment limits (as SocketCAN's can_bittiming_const), for a host that computes timings itself.

Tdc::Auto leaves the transceiver delay compensation to the device (offset at the data sample point), and the answer says the offset it set. A setting the controller doesn't have is Common(Unsupported), a bit rate it can't reach Common(InvalidArgument). configure takes the controller off the bus and back as its hardware needs (frames queued for sending stay queued) and ends in CanConfig::mode.

let actual = node
    .can()
    .configure(CanConfig {
        mode: Mode::Normal,
        nominal: Timing::Rate { rate: Baud::kilobaud(500u16), sample_point: 875 },
        fd: Some(FdConfig {
            data: Timing::Rate { rate: Baud::megabaud(2u8), sample_point: 750 },
            tdc: Tdc::Auto,
            iso: true,
        }),
        options,
        bus_off_recovery: Some(Second::milliseconds(100u8)),
    })
    .call()
    .await?;
let nominal = actual.nominal.segments().unwrap(); // e.g. prescaler 1, seg1 139, seg2 20 at 80 MHz

Debuggers¶

configure sets a node up in one call. A bus debugger keeps every step in hand:

  • set_mode switches the mode alone, keeping bit timing, filters and layout: Mode::Config to stay off the bus (TX recessive) for configuration-only steps, then Restricted, ListenOnly, a loopback, Test, Sleep or back to Normal. Items that need configuration mode (set_layout, set_filters on most controllers, CanTimeTriggered::configure_tt) switch through it and back by themselves, and stay in it when called there.
  • protocol_status() reads the controller's raw protocol state: activity (synchronizing, idle, receiving, transmitting), the counters, its error logging counter, last error codes of both phases, flags of the last received FD frame, protocol exceptions, the measured transceiver delay and message memory ECC errors. Reading resets what the controller resets on a read.
  • bus_errors reports every error with kind, phase and direction; test_pins drives TX and reads RX.
  • Raw register access is not part of this crate: a device that offers it implements ww_memory next to it.
let can = dev.can().interface(0);
can.set_mode(Mode::Config).call().await?;
can.set_layout(MemoryLayout { standard_filters: 64, ..layout }).call().await?;
can.set_filters(filters).call().await?;
can.set_mode(Mode::ListenOnly).call().await?;
let ps = can.protocol_status().call().await?;

Measured on the device¶

What the device sees better than the host is measured there:

  • receive, TX event and bus error times (stream heads, see Time);
  • TxEvent::queued: how long a frame waited from the device accepting it to its start of frame (queue, arbitration, retransmissions);
  • bus_load: busy time of the bus per window, frames and error frames, sent to observers once per window;
  • ProtocolStatus::tdc_value: the transceiver loop delay the controller measured;
  • detect_timing(candidates, per_candidate): listens without acknowledging at each candidate timing and answers the first one a frame came in at without errors, leaving the controller configured with it in ListenOnly.

Sending and receiving¶

let mut rx = node.can().rx().call().await?;
let mut tx = node.can().tx().await?;
tx.send_owned(TxFrameOwned { frame, marker: Some(UNib32(1)) }).await?;
while let Ok(event) = rx.recv_event().await {
    if let StreamEvent::Item { t, value, .. } = event {
        println!("{t:?} {:?} {:02x?}", value.frame.id, value.frame.data);
    }
}

rx is a counted stream: every event head carries the frame's position, the frames the device lost right before it (a full receive FIFO, a full link buffer) and the time it was received. tx is a credit sink in bytes of serialized frames; a frame the controller can't send as configured (FD with FD off, anything in a mode that doesn't send) is dropped and reported as TxOutcome::Rejected on tx_events.

Time¶

Received frames, TX events and bus errors carry their time in the event head: a Second of the device's one clock (ww_timebase::Clock), in the prefix and number type the device picks (usually a u32 of µs, which wraps every 71.6 minutes; the host unwraps it around Clock::now()). Capabilities::timestamps says how fine it is and where in the frame it was taken: start of frame (M_CAN, bxCAN in TTCM, MCP2518FD), end of frame (gs_usb), or by software when the frame was read out (no hardware timestamps); None, and heads without a time, on devices without a clock.

Status, sleep and errors¶

status is an observable read-only property: Status { state, tec, rec, last_error, last_data_error }, state being Stopped, Active, Warning, Passive, BusOff or Sleeping. The device sends it to observers when the state changes:

let mut status = node.can().observe_status().await?;
while let Ok(s) = status.recv().await {
    if s.state == ErrorState::BusOff { node.can().recover().call().await?; }
}

Mode::Sleep puts the controller to sleep; with Options::wake_on_bus bus activity wakes it, back in the mode it was in, and status goes from Sleeping to Active. The transceiver is switched separately (set_transceiver: Standby, Silent, Sleep); its transceiver_state property reports wiring faults (CAN_H / CAN_L open or shorted, dominant timeout, over temperature) as they appear.

Methods return CanError: CommonError as Common (unsupported, invalid argument, in use, wrong state, ...), plus OutOfFilters { max } (fall back to fewer or wider filters), OutOfMemory { available } (a smaller layout or schedule) and BusOff (recover first). Each method lists what it returns with #[errors(..)]. Errors on the bus are not errors of a call: they are counted in Status and reported one by one on bus_errors.

Filters, memory and dedicated buffers¶

node.can().set_filters(FilterConfigOwned {
    filters: MaxLen::new(vec![
        Filter { matching: FilterMatch::Exact(CanId::standard(0x100).unwrap()), action: FilterAction::Buffer(2) },
        Filter {
            matching: FilterMatch::Range { from: CanId::standard(0x200).unwrap(), to: CanId::standard(0x20F).unwrap() },
            action: FilterAction::Fifo { fifo: 0, high_priority: false },
        },
    ])?,
    non_matching_standard: NonMatching::Reject,
    non_matching_extended: NonMatching::Accept { fifo: 1 },
    reject_remote: false,
}).call().await?;
let latest = node.can().rx_buffer(2).call().await?; // the last 0x100 frame, if one came

The first matching filter wins. A device maps the list to its hardware (filter banks, elements, masks) and answers OutOfFilters or Unsupported (a range on a mask-only controller) when it can't. On controllers with a configurable message memory (Capabilities::memory, in 32-bit words), set_layout sets how many filters, FIFO and buffer elements and TX events it holds and how many data bytes an element takes; controllers of a group share the memory, so a layout that doesn't fit next to the others is OutOfMemory. tx_buffer(index, Some(frame), Some(period)) makes the device send a frame cyclically (a heartbeat) until the buffer is written again or cleared with None.

Time-triggered CAN¶

#[ww_trait]
pub trait CanTimeTriggered {
    fn configure_tt(config: Option<TtConfig>) -> Result<Option<TtConfig>, CanError<'i>>;
    fn set_schedule(triggers: MaxLen<RefVec<'i, Trigger>, MAX_TRIGGERS>) -> Result<(), CanError<'i>>;
    property!(ro tt_status: TtStatus);
}

TtConfig sets the ISO 11898-4 level, the role (slave, or potential time master with a priority), the reference message ID, the matrix cycle length and the network time unit; the controller must be in Mode::Config or Mode::Off. The schedule is a sorted list of triggers (time mark, cycle repeat and offset, and what to do: send the reference message, send a TX buffer exclusively or in a merged arbitrating window, check a reception, watch, end of list), bounded by the trigger memory (OutOfMemory). tt_status reports synchronization, master role, the basic cycle and the error level.

Tests¶

tests/io_can runs two mock nodes end to end through the real host event loop: a full node with every optional item (internal loopback through the filters, TX events with markers and queue times, bus-off and recovery, explicit modes and configuration steps, raw protocol status, timing detection, bus load, sleep and wake-up, transceiver, buffers, terminator, test pins) and a minimal node with all of them left out. tests/io_can_group runs a group of two controllers (clock selection, enable / disable, independent interfaces), time-triggered operation and CAN XL frames.
