## Unreleased

### ⚠️ Breaking

- Test fixture `nucleo_g0b1re_api` 0.4.0: the pinned signatures of `Clock`, `LastReset`, `Counters` and `Indication` follow `ww_si` 0.5.0 (EVO-51), as they did for EVO-47.
- Across a wire break resources are matched by path and `#[moved_from]` (EVO-40), no longer by position: on a new line, a resource replaced in place is reported removed and its successor added (not renamed), one at another position is a wire change only, and an own struct or enum replaced by another in a resource is reported as replaced, not compared field by field (`TypeCheck::own_types_by_name`, `Bounds::own_types_by_name`). `compare_recorded` takes the new version's moves as a fifth argument (`&[]` for none). `Report` has new public fields `across_line`, `proposals`, `moved_from_errors` and `unverified_moves`, `NoSnapshot` a new public field `previous_line`, `Rule` a new variant `MovedAcross`: struct literals and exhaustive matches add them.
- w0, the design line (EVO-41): `Check::save` keeps no snapshot of a crate or API root on `w0.x`, the new `SaveStatus::DesignLine` says so; its first snapshot is saved once it moves to `w1.0`. `Check::run` on a w0 crate passes, with `strict` and `require_current` too: against a snapshot that exists (one kept from before, or `against`) the report is information and needs no bump of either kind (`Comparison::design_line`, `NoSnapshot::design_line`), and `Report::check_wire` asks no wire bump between two w0 versions. A crate that can be published with a root on w0 gets a warning (`Comparison::warnings`, `NoSnapshot::warnings`, `Outcome::warnings()`, `Saved::warnings`). Code building `Comparison` or `NoSnapshot` with a struct literal or matching `SaveStatus` exhaustively adds the new fields and variant. `Outcome::NoSnapshot` holds a `Box<NoSnapshot>`, as `Compared` does.
- The checker per API root (EVO-39): `Outcome` has a new variant `Roots(Box<RootsOutcome>)` for a crate with several roots, so an exhaustive `match` adds an arm. `Comparison` has new public fields `unchanged_since` and `root`, and `SaveStatus` a new variant `Removed`, so a `Comparison { .. }` literal and an exhaustive `match` on `SaveStatus` need them. `snapshot_files::latest_snapshot` skips a root's own files, which it took for whole-crate snapshots.
- Test fixture `nucleo_g0b1re_api` 0.4.0: the pinned signatures of `Clock`, `LastReset`, `Counters` and `Indication` follow `ww_si` 0.4.0 (EVO-47), as they did for EVO-44.
- Units are compared by quantity (exact_units UNIT-8, EVO-45): a step carries a `ww_self::units::QuantityExprOwned` for the old kind; another quantity of one dimension (`Of<Height, Meter>` vs `Of<Width, Meter>`) is a `Rule::Meaning` break, a unit that gained a quantity under its name the note `quantity of its own added`.
- Test fixture `nucleo_g0b1re_api` 0.4.0: the pinned signatures of `Clock`, `LastReset`, `Counters` and `Indication` follow `ww_si` 0.3.0 (EVO-44), as they did for SW-24 and NUM-19.
- Units are compared on exact_units UNIT-10's `Dim` (EVO-44): a `MarkerDef::Base` is read as a unit, and dimensions combine with `DimOwned::checked_mul`.
- Snapshots per API root (EVO-38): `Check::save` returns `Vec<Saved>`, one per snapshot written or checked; `Saved` has new public fields `root` (`Some("wire_v2::Thermo")` for a root's snapshot) and `warnings`, so a `Saved { .. }` literal needs them. A crate with one root or none still gives one `Saved`.
- Unit definitions are read from `exact_units::UnitDef` (STD-106): the kind from its `quantity`, a conventional value from its `provenance`; an origin's reference is a `MarkerId` and shown by it (`exact_units::AmbientPressure`, `the unit's zero` for `UnitZero`). Same verdicts as before.
- The wire version is checked apart from the crate version (EVO-27): `Check`'s verdict and `Check::save` fail when the declared wire version is lower than the changes need, goes back, or is no longer declared, naming the version to declare and where (`#[ww_api_root(wire = ..)]`, or `[package.metadata.wire_weaver] wire` in `Cargo.toml` for a crate without an API root). A `#[since]` newer than the crate's wire version fails the check too, instead of being a warning: it is in the new `Report::since_too_new`, no longer in `Report::warnings`. Code that only checked `Report::check_version()` calls `Report::check_wire()` as well. `Report` has new public fields `old_wire`, `new_wire`, `wire_bump`, `wire_reasons` and `since_too_new`, so a `Report { .. }` literal needs them. `compat::signature_change` returns the new `SignatureChange` (`message`, `arguments_changed`) instead of a `String`.
* `#[since]` hints and checks use the API root's wire version (EVO-24): an addition is expected with `#[since = "<new wire version>"]` (`... and a wire bump` when the revision wasn't bumped), a marker newer than the root's wire version is reported (`newer than the API's wire version w1.1`). A crate without an API root (a `ww_stdlib` crate until EVO-26) only gets `added without #[since]`. A change of the root's wire version is listed in the report (`wire version w1.0 -> w1.1`) and in `diff` (`wire version`); `ApiBundle::wire` missing from an older snapshot is not compared.
- A float `Fixed` refuses NaN unless its bound is `MaybeNan` (STD-105, exact_units NUM-19): `MaybeNan` -> any other bound (and back, for the side that refuses) is a bound narrowed, and a plain `f32`/`f64` -> a NaN-free float `Fixed` is now breaking (`a NaN the old version writes is refused by the new version`); to `Fixed<.., MaybeNan>` it stays compatible.
- `check_signature` compares the arguments of methods and stream functions as the fields of their `Unsized` args struct (EVO-22), with a `#[flatten]` argument's struct fields in its place, instead of failing on any difference in their number. A newer client's trailing arguments are compatible (the device skips them), a newer device's need a default (`argument `x` is not sent by the old version and has no #[default]`, `Rule::Resource`). When the wire stays compatible but Rust callers break (arguments added or removed, an argument list promoted to a `#[flatten]` struct), the finding has the new `Rule::Signature`, with its own message from `compat::signature_change`, never the wire rule's text. Code matching on `Rule` exhaustively adds the variant. New `Rule::keeps_wire()`: the rule is about Rust code only.
- Signatures of skipped definitions are not compared when the old snapshot lacks a model field that signatures include (`ww_self::signature::includes`, the `Argument` fields of EVO-22), as EVO-13 does for the comparison itself: upgrading wire_weaver alone reports no change.
- `compat::Unwrapped` has a new public field `same` (`"same bytes"` for a transparent wrapper, `"same value"` for a unit, scale or origin spelled differently), so an `Unwrapped { .. }` literal needs it. `Rule::Meaning`'s `doc()` points at the new page `docs/evolution/units_by_meaning.md`.
- `snapshot_files::latest_snapshot` returns `Option<Snapshot>` (new, from the new `snapshot_files::read`: `path`, `bundle` and `recorded`, what the file recorded) instead of a path and bundle. `Report` has a new public field `unrecorded`, so a `Report { .. }` literal needs it.
- `Finding` has a new public field `root: Option<compat::RootCause>` (EVO-21): a `Finding { .. }` literal needs it, `Finding::new` still builds one without it. `compat::Bounds` and `compat::TypeCheck` gained `root` as well, so their own literals (already needing `rule` and `unwrapped`) need it too.

### 🐛 Fixes

- A crate with several roots: a type or trait is shared only when the roots reach the same item, matched by its path in the crate (`common::Channel`), no longer by name (EVO-42). A root with a `Channel` of its own (`wire_v1::Channel`) was reported as also reaching `common::Channel`, and a change to either was named on the other's roots. `SharedChange::item` is that path (`shared `common::Code` changed on ..`), a trait's from `SourceNotes::trait_modules`, a type's from its path in the model. Tests `same_name_in_two_modules_is_not_shared` (both directions).
- Two structs or enums of one name in two modules (`geometry::Point` and `other::Point`, API-46) are two types to the checker: the crate's own types were collected by name, so one stood for both, and a change to the other was compared against the wrong definition or missed. They are named by their path in the crate where names collide (EVO-42). Test `two_types_of_one_name_in_one_root`.
- Findings on a new wire line read cleanly (EVO-33). The root crate's own traits and types are no longer reported as "on different wire lines" (`a wire break because trait thermo_api::Channel changed`, with the old crate version as the new side's label): `compare` gives both sides the old crate version, so a pair of the same version is one source. Every difference of a type is reported, not the first: all fields that differ, and the markers together with the other generic arguments (`Sample::temp` says both the scale and the storage, `Centi` -> `Milli` and `i16` -> `i32`), joined by `; `.

- A removed enum variant is a breaking change (EVO-28): `compare` used to say nothing about it, so a crate dropping `Mode::Triggered` passed with a patch bump while every Rust `match` on it broke. The finding has the new `Rule::VariantRemoved`, which keeps the wire when the enum has a catch-all (`Rule::keeps_wire()`); without one the type check reports the wire break as before. Code matching on `Rule` exhaustively adds the variant.
- A `#[since]` newer than the crate's own version is warned about on every resource, field and variant of the crate, not only on additions: a host built with it refuses that item on every device of this version. Additions with a `#[since]` older than the new version are still warned about as before.
- The scales of a product and a quotient of two `Fixed` values, `Product<A, B>` / `Quotient<A, B>` (STD-83), are compared by their factor as other scales are: `Product<Milli, Milli>` for `Micro` is the same value, `Quotient<Milli, Milli>` for `Product<Milli, Milli>` is breaking.
- `exact_units::Fixed` (what `ww_si::Fixed` re-exports since STD-61) is recognised as `Fixed`, so `Quantity` -> `Fixed` gets its hint again; a marker with its definition in the snapshot (INT-13) comes back in-line and is named without its module path in findings.
- Upgrading wire_weaver alone no longer fails `Check::require_current` or reports a change (EVO-13): a field of the API model that a snapshot file has in no instance (written by an older wire_weaver, like `ItemEnum::future_version` from EVO-10 in a snapshot saved before it) is not recorded, and both sides are compared without it, instead of the source counting as changed. The rule needs no list of fields or `ww_self` versions, so the next field added to the model gets it as well (with shrink_wrap DER-17, also one that is not an `Option`). New `recorded` module (`Recorded`, `Unrecorded`), `compare_recorded(old, old_recorded, new, new_recorded)`, and `Report::unrecorded`, printed as "not compared: ..". `Check::save` reports a file that only lacks such fields as `SaveStatus::Reformatted`, never as refreshed. Test with the snapshots of `nucleo_g0b1re_api` 0.3.0 / 0.4.0 as saved by an older wire_weaver (`tests/check.rs`).

### 🚀 Features

- `Check::cache(CrateCache)` (EVO-50): a `Check` holds a `wire_weaver_core::CrateCache` again, its own unless given one, which its clones share; checks given one cache (a `save` then a `run`, crates with the same dependencies) walk the dependencies' source once, also on other threads. The cache sees edits, so a run after one checks the source as it is then, and `Check` stays `Send` and `Sync`.
- `#[moved_from]` (EVO-40): `compare_moved(old, new, moves)` with `Move` (from `wire_weaver_core::MovedFrom`) verifies that a resource moved across a wire break is exactly the same as the one it names and reports one move (`Rule::MovedAcross`); an attribute that names nothing, a resource with another signature or a place on the API's own line fails `Report::check_wire`, as do a revision newer than the old version or older than the resource's `#[since]`, an attribute naming its own place, two naming one place and a source still there on the new version. Moves to another line than the old version's (an older link of a chain, a later revision of the new line) go to `Report::unverified_moves`; `verify_move` checks one against a snapshot of its line, and `Check` does so with the line's latest snapshot, warning when there is none. A resource added with the name of one removed elsewhere is never matched, only listed in `Report::proposals` (with the attribute suggested when the signature is the same). `Check` reads the moves from the source; a new line's root in a crate with several is compared with the previous line's root of the same name for them (`NoSnapshot::previous_line`, failing only on a `#[moved_from]` that doesn't hold).
- `Finite` bounds (exact_units NUM-20, STD-104): `Unbounded`, `MaybeNan` or a plain float read as `Finite` is a bound narrowed; a float range fits inside `Finite`.
- An origin moved to another reference says why its points don't convert (STD-108): a zero known only at run time, a device clock that needs a clock sync, or a leap-second table between POSIX time and TAI; a reference whose `HOW` changed under the same id is a `Rule::Meaning` break too.
- The checker per API root (EVO-39): `Check::run` of a crate with a `[package.metadata.wire_weaver.roots]` table checks each root against its own latest snapshot (`RootsOutcome`, one `RootOutcome` per root), instead of refusing it. Each root's wire version and `#[since]` are checked on its line, and a wire bump it needs names its entry in the `roots` table. A type or trait of the crate that more than one root reaches and that changed is listed once with every root and line it changed on (`SharedChange`), and the roots that reach it with nothing to compare (a w0 root, `SharedChange::also`); a w0 root's report adds nothing to the crate bump. The crate version must be bumped for the root that needs the most (`RootsOutcome::minimal_version`). A root whose latest snapshot is older than a crate version that saved other roots stands for that version (`Comparison::unchanged_since`), so a change after the save needs a new version, as for a whole crate. `require_current` works per root: a root unchanged since an older version's snapshot needs no file of its own. A root on w0, the design line (EVO-41), is checked as a whole crate on w0 is: no snapshot needed, differences are information, and the publishable-crate warning is given once in `RootsOutcome::warnings`. A root the table no longer lists while it has snapshots is a breaking crate bump of the last version that shipped it, the newest one saved before the current version while the root had a snapshot, alike for `run` and `save` (`RemovedRoot`); `Check::save` records the removal in `<crate>_<version>.<module path>.<Trait>@w<line>.<revision>.removed` (`snapshot_files::removed_file_name`, `SaveStatus::Removed`), so later versions aren't asked again, and an evolution test with `require_current` fails until it is recorded. `Check::against` takes a root's snapshot file and checks that root; a root's snapshot file checked by itself is compared with the previous one of the same root. `snapshot_files::crate_files` lists a crate's snapshot files by name, `Difference::path` gives a difference's path.
- One `wire_weaver_core::CrateCache` per `Check::run` and per `Check::save` (EVO-39), which `check` re-exports: the roots of a crate walk their dependencies' source once.
- A unit that moved to another system of units (exact_units UNIT-9: SI, Natural, Gaussian) is breaking under `Rule::Meaning` with its own reason, `another system of units (Si vs Gaussian)`, also where the same bytes would hold the same value (1 G and 10⁻⁴ T): crossing takes a named step.
- `NumericBaseType::INib32` is a `Variable { align: 4, granularity: 4 }` size class, the same as `UNib32` (SW-24).
- Snapshots per API root (EVO-38): `Check::save` saves a crate with several roots (`[package.metadata.wire_weaver.roots]`, EVO-37) as a snapshot per root, `api_snapshots/<crate>_<major>_<minor>_<patch>.<module path>.<Trait>@w<line>.<revision>.ron` (new `snapshot_files::root_file_name`, `root_of_file_name`, `RootFileName`), each checked against the root's previous snapshot: the newest of its own files, or of the crate's whole-crate files from before it had several roots whose wire version is on the root's line and that have a root trait of that name (new `snapshot_files::root_snapshots`, `RootSnapshot`). Only the current crate version's files are written, so a released snapshot never changes: a root that didn't change since keeps its previous file as its latest. Nothing is written when any root is refused, and a refusal names the root and its entry in the `roots` table. A root with no earlier snapshot while the crate has older ones is saved with a warning in `Saved::warnings`, naming what was looked for and what is there (a renamed or moved root matches nothing by name). `Check::run` refuses such a crate until it is checked per root (EVO-39).
- Test `snapshot_pairs`: every saved snapshot of `ww_global`, `ww_tap` and the `ww_stdlib` crates is checked against the one before it, crate and wire version (EVO-27), as `ww api check <snapshot>` does. It found `ww_si` 0.1.0 and 0.2.0 on one wire line across a wire break, and `ww_board_info` 0.1.0 and 0.2.0 snapshots that didn't record a catch-all their enums had.
- Both bumps from one comparison (EVO-27): new `WireBump` (`None`, `Revision`, `Line`, with `apply` and `between`), `Report::wire_bump` and `Report::wire_reasons`, `Report::minimal_wire()`, `Report::check_wire()` and `Report::required()` (both bumps in one line, `wire w1.0 -> w1.1 or later (a new wire revision), crate 0.1.0 -> 0.2.0 or later (...)`, printed by `Comparison`'s `Display` as `needs:`). A finding whose rule doesn't keep the wire, or a dependency crate on another wire line, needs a new line; an added item, trait, type, field or variant, trailing arguments added or removed, a raised max length, an assigned `ww_global` id or a dependency at a newer revision of its line a new revision; doc comments and Rust-only breaks none. A dependency on a new line and the breaks it causes are one reason (`shared_api on a new wire line, w1.0 -> w2.0 (2 wire breaks because type shared_api::Shared changed)`, EVO-21). Any bigger bump passes, such as a new line by hand for a change of meaning.
- Several broken items caused by the same dependency change are grouped under it instead of reading as unrelated breaks (EVO-21): new `compat::RootCause` (`what`, `crate_id`, `name`), set once, closest to the source, when a resource or type check fails because a trait, type or marker from another crate has an incompatible version or a different definition under the same one; `Finding::root`, `Report::breaking_groups()` (roots reached by 2+ findings, the rest in their original order), and `ww api check`'s report prints each such group as `N broken because <kind> <crate>::<name> changed:` before the items it reaches (`docs/evolution/checker_tool.md#several-broken-items-one-cause-evo-21`).
- `missing_test_warning(crate_path)` (TOOL-31): `None` when `<crate_path>/tests/evolution.rs`
  calls `wire_weaver_evolution::Check`, else a message naming the file and what to add, for `ww api check` / `ww
  api save` to print as a warning. Only reads the file's text, so it works even when the crate can't be parsed.
- Kinds of quantity compared (STD-68, with EVO-17): one step of a number has the kind of its unit as well as the dimension and factor, so the same bytes in another kind of one dimension are breaking under `Rule::Meaning` (`Per<Volt, Volt>` -> `Ratio` or `Per<Ampere, Ampere>`: `ratio of .. vs plain, another kind of quantity`; `Per<Volt, Ampere>` -> `Ohm`: `plain vs resistance`). A unit that gains a kind of its own under its name (`Ohm` with this `exact_units`) keeps its values: compatible, listed as `kind of its own added`.
- `Check::snapshots_dir(dir)`: the crate's snapshots are in `dir` instead of its `api_snapshots/` (a crate from another repository, its snapshots kept here).
- A variant appended with a discriminant beyond a narrow catch-all (`#[future_version] Unknown(u8)` / `Unknown(u16)`, DER-25) is breaking: an older reader fails on it. Reports name the catch-all with its width (`Unknown(u16)`), so a changed width is `Rule::CatchAll`.
- Units compared by meaning (EVO-17): a marker with a definition in the API model (INT-13) is compared by it, no longer by name. The unit and scale of a `Fixed` are multiplied into one step (dimension and exact factor): another spelling of the same step is compatible and listed as `same value` (`Milli` -> `Pow10<-3>`, `Fixed<Volt, Milli, ..>` -> `Fixed<MilliVolt, One, ..>`, `Per<Meter, Second>` -> `MeterPerSecond`); the same bytes in another scale are breaking under `Rule::Meaning` with the factor (lbf·s vs N·s: `the same bytes in another scale, 1 on the old version is 4.448222 (exactly 1·…) on the new version`), another dimension too. A unit, scale or origin of the crate's own redefined under the same name is breaking, a new symbol is not; a marker of a kind the checker doesn't know is the same only when its definition is. Origins of points by dimension, reference, zero and period (`Angle<Degree>` = `Angle<Radian>`, `Celsius` vs a zero at 298.15 K breaking). `Wrapping` and `Saturating` (STD-63) in the place of a bound: `Saturating` is `Unbounded`'s values, `Wrapping` on one side only is breaking. A unit by convention (`UnitDef::provenance`, STD-72) whose value or source changed under the same name is compatible and listed as `conventional value updated`; defined <-> conventional is breaking. `wire_weaver_client` gets the same at connect time. Skipped `ww_si` definitions are read from the snapshot only when a marker is compared. Docs: `docs/evolution/units_by_meaning.md`.
- `ww api check` also shows unit-suffix hints (TOOL-22) from `wire_weaver_core::load_crate_with_hints`: `Comparison`/`NoSnapshot` gained `hints: Vec<UnitHint>` (re-exported), `Outcome::hints()`, and their `Display` prints each as `note: ..`, never affecting `verdict()`.
- Transparent wrappers, markers and bounds (EVO-15): a `transparent` struct (DER-18, `ww_si::Fixed`) on one side and its field's type on the other is compatible and listed (`Api::set: argument `shared`: u64 -> Fixed<Second, Micro, u64, Unbounded>, same bytes`); a type parameter no field uses is a marker whose argument is compared by name, so a changed unit or prefix is breaking under the new `Rule::Meaning` (same bytes, another quantity), as is one wrapper replaced by another; bound markers (`Unbounded`, `Range`, `RangeU64`, `RangeDec`, by name) are compared by value and any change is breaking under the new `Rule::Bound`, the finding saying which side writes and which refuses. `compat::TypeCheck` and `compat::Bounds` gained `rule` and `unwrapped` (new `compat::Unwrapped`), so a `Bounds { .. }` literal needs them; an exhaustive match on `Rule` needs the two arms. `wire_weaver_client` uses the same checks at connect time: a device whose unit or bound differs from the client's is now incompatible for that resource. A `ww_si` type the API model skips (`Fixed` in your API) is read from the `ww_si` snapshot built in, so it is checked as an in-line wrapper is. `ww_si::Quantity` -> `ww_si::Fixed` is breaking, and the finding says it is the intended move, for a major version.

- A variant appended to an enum with the `#[future_version]` catch-all (SW-47) is a compatible change (EVO-10): an older reader gets it as the catch-all, when it can skip the variant's fields (`Unsized`, or a unit variant). Without the catch-all, or with a snapshot saved before EVO-10 (the error says to save it again), it stays breaking. A variant found under another discriminant on the other side (inserted before others, reordered) is reported as moved, before any unknown-variant check. Adding, removing or renaming the catch-all is breaking under the new `Rule::CatchAll` (Rust type, not wire); an exhaustive match on `Rule` needs the arm.
- `Check::require_current(true)` (EVO-12): the snapshot of the crate's current version is required, so a version can't ship without one. Fails when it is missing (naming `just api-save`, `WW_API_SAVE=1 cargo test --test evolution` and `ww api save`) or when the source differs from it, and compares the previous version's snapshot with it for the bump. `NoSnapshot` and `Comparison` gained `current_required` (and `NoSnapshot::previous`).
- `Check::save(force)` writes the snapshot of the crate's current version, or refreshes it when the source changed, never an older version's; it refuses a version not bumped enough since the previous snapshot unless `force`. Returns `Saved { path, status: SaveStatus, previous, bundle }`. `Check::assert()` saves first when `WW_API_SAVE` (`SAVE_ENV`) is set, so an API crate saves from its own `tests/evolution.rs` with the checker its lock file pins.
- New crate (EVO-11): the evolution checker of `ww api check`, moved out of `wire_weaver_client::evolution` so an API crate can run it from its own test without the client (tokio, probe-rs, nusb). `compare`, `diff`, `Report`, `Change`, `Bump` and `Difference` as before; `compat` holds the per-resource and per-type rules shared with the client (`compare_items`, `TypeCheck`, `Bounds`).
- `Check::new(crate_dir).strict(true).assert()` (feature `source`, default): parses the crate from source (`wire_weaver_core`), compares it with the newest fitting snapshot in its `api_snapshots/` and panics when the version is not bumped enough, or, in strict mode, when there is no snapshot. `Check::run()` returns an `Outcome` (`Compared(Comparison)` or `NoSnapshot`) and `Outcome::verdict()` the line or error `ww api check` prints.
- Breaking changes name the rule they break: `Report::breaking` is a list of `Finding { rule, message }`, `Rule` (`Removed`, `Renamed`, `Moved`, `GlobalId`, `Resource`, `Type`, `MaxLen`, `FieldKind`, `Optional`) with `summary()` and the docs section in `doc()`. A failed check says the version needed, that a version with a snapshot is released and never changes, which line of `Cargo.toml` to bump and to record the release with `ww api save`.
- `snapshot_files`: `SNAPSHOTS_DIR`, `parse`, `latest_snapshot`, `triplet`, from `ww api`.
- A dependency's trait or type is compared by its crate's wire line when both sides declare a wire version (EVO-26, `ApiBundle::ext_wire`): a `ww_stdlib` crate's Rust-only break (0.3.0 -> 0.4.0 on wire `w1.x`) is no longer "from incompatible crate versions" in `ww api check` or the client's connect-time check; different lines are breaking, named (`from ww_board_info on different wire lines: w1.2 vs w2.0`). Crates that declare no wire version keep the crate-version rule.
